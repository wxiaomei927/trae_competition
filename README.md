# 字源 · 汉字形音义溯源

> 输入一个汉字，看它从甲骨文到楷书的字形演变、读音流变与义项衍生。

云南大学 TRAE 校园 AI 创意实践挑战赛 · S8「AI × 文学」赛道 · 题四「字源」

## 问题

汉字的形、音、义分属三套系统，却被拆散在不同工具里。想查一个字怎么来的，得先查字形数据库，再查《广韵》反切，再翻注疏书证——每查一次换一次界面，普通人根本走不完这条路。

尤其对非专业读者来说，"这个字为什么长这样""这个字以前是什么意思"这两个最基本的问题，现有工具基本答不了。而这恰恰是汉字最迷人的地方：**一个字是一个微型史诗**，甲骨文里它画的是啥，读音怎么从上古走到今天，意思又如何一路引申，全都在一个字里。

## 方案

「字源卡」把一个汉字的形、音、义三条线索叠进同一张卡片，用一条可以走进去的**三维字形演变链**串起来：

- **字形演变**：甲骨文 → 金文 → 小篆 → 隶书 → 楷书，五帧沿纵深轴排开。拖动时间轴，字形向远处退去又从近处浮现，视野里始终保留整条演变链的上下文，像在时间的长廊里回望。
- **读音流变**：中古反切、中古声母韵目声调、郑张上古拟音与现代读音对照，多音字按义项分列对应（如「行」的 xíng／háng／xìng 各自对应不同义项）。
- **义项时间轴**：本义 → 引申义 → 假借义按年代排列，每条义项附书证原句、出处与白话翻译，可回溯核对。
- **六十秒故事**：把形音义串讲成一段可直接朗读的口播文案，并导出可分享的字源卡图。
- **生词本**：一次批量导入十个字，批量出卡。

## AI 是怎么用的

AI 参与三处，全部**预生成后写入本地 JSON**，页面标注「AI 生成」：

1. **口播文案** —— 把形音义串成 50—70 秒的可朗读文案
2. **今世用例** —— 生成现代语境用例与易错用法提醒
3. **一句话意象** —— 点明字的关键意象与心境

关键设计是**双轨兜底**：所有 AI 内容都有本地预生成的版本，调用失败时自动回落。现场断网或接口不可用，演示不中断。造字法判断与「六书」归属等有学术争议处，一律标注「一说」，不把单一观点当定论。

## 演示亮点

- **三维字形演变链**：纯 CSS 3D（`preserve-3d` + `translateZ`）实现，含景深衰减、透视反向补偿与弧线排布，让五个朝代在空间上真实展开，而非平铺的五张图。当前帧恒定居于画面中央，鼠标移动产生轻微视差。
- **宣纸墨韵背景**：Canvas 生成的缓慢漂移墨晕与金色光尘，叠加 SVG 纤维纹理。梦而不飘——这是"字从地下走到纸上"这个主题本身的一部分。
- **可分享字源卡**：Canvas 离屏绘制导出 PNG，含字形演变带、读音反切、义项书证与印章。

## 赛题要求对照

> 依据 `“AI x 文学” 参考题包.pdf` 题四「字源 —— 一个汉字的形·音·义溯源」

**基础项 6/6 全覆盖**：字形演变序列（每帧附年代字体名，可横向滑动对比）· 构形解读（造字法＋构形解析，争议处标注「一说」）· 义项时间轴（每义附书证原句＋出处＋白话翻译）· 读音流变卡（中古反切对照，多音字按义项分列）· 60 秒故事（可朗读文案＋可分享字源卡图）· 批量导入生词本（一次 10 字，批量出卡）

**进阶项 4/4 全覆盖**：字族联想（同形旁字族树）· 部件动画（拆字工坊逐部件演示）· 生活例句（AI 生成现代语境用例含易错提醒）· 谜题模式（看字形猜字，答对解锁字源卡）

**数据自评**：172 条义项书证全部带出处（缺 0 条）· 19 个多音字按义项分列对应 · 帧数分布 51 字 5 帧／8 字 4 帧／1 字 3 帧 · 口播文案时长全部落在 52—69 秒

> 备注：数据包未提供 `char_truth.json`（10 字人工核验真值），故"构形解析一致率 ≥80%"与"义项顺序一致率 ≥90%"两项锚点无法本地自评，改为路演中说明口径。

**合规**：字形图像与书证取自公有领域文献（《说文解字》《广韵》等）并注明出处；未用现代字库字形冒充古文字；「六书」归属等争议处标注「一说」，不把单一观点当定论；AI 参与方式在路演中说明。

## 技术栈

Vue 3 + TypeScript + Vite。数据管道由 `scripts/build-data.mjs` 从组委会数据包生成 `src/data/characters.json`（60 字 × 290 张字形图 + 172 条义项 + 82 条读音），字形资源为公有领域文献整理的 SVG 矢量图。

## 本地运行

```bash
npm install
npm run data     # 从数据包生成 characters.json（仅首次需要）
npm run dev
```

构建与部署：

```bash
npm run build    # 输出到 dist/
```

仓库配置 GitHub Actions（`.github/workflows/deploy.yml`）自动部署至 GitHub Pages。

## 目录结构

```
scripts/build-data.mjs       # 数据管道：数据包 → characters.json + public/glyphs
scripts/shot.mjs             # 截图脚本（开发自检用）
public/glyphs/<字>/          # 290 张字形图（SVG 矢量 + 楷书 PNG）
src/
  data/characters.json       # 生成物：字形帧 + 义项 + 读音
  data/char_analysis.json    # 造字法 / 构形解析 / 口播文案 / 生活例句
  components/
    InkBackdrop.vue          # 宣纸墨韵背景（Canvas 墨晕 + 光尘 + 纤维纹理）
    GlyphTunnel.vue          # 三维字形演变链
    InfoPanel.vue            # 义项时间轴 / 读音流变卡 / 书证引文
    OriginCard.vue           # 字源卡 PNG 导出
  styles/tokens.css          # 设计系统（宣纸 / 墨 / 朱红 / 金）
```

## 数据现状与已知限制

- 数据包实际覆盖 **60 字**、**290 张字形图**；其中 `城 湛 環 賜 賞 過 道` 无甲骨文帧，`中` 无楷书帧。界面按实际帧数自适应渲染，缺帧不占位、不以其他字形顶替。
- CSV 均为 UTF-8 带 BOM，`年代` 与 `对应义项` 为自由文本，解析后按语义排序。
- 赛题要求的 `char_truth.json`（10 字人工核验真值）**未随数据包提供**，因此"构形一致率 ≥80%""义项顺序 ≥90%"无法本地自评；改为在路演中说明口径。
- 「六书」归属等学术争议处一律标注「一说」。

## 数据来源与版权

- 字形演变图、义项书证、读音材料均取自公有领域文献整理，每条附出处
- AI 生成内容均标注「AI 生成」
- 原始数据包由组委会发放，置于 `assets/`
